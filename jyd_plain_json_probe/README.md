# 剪映自动化生成项目

开发、调试、扩展和打包请先阅读 [开发者指南](docs/DEVELOPER_GUIDE.md)。普通安装与使用从 [START_HERE.md](START_HERE.md) 开始。本轮数字人账号与任务收件箱改造见 [数字人任务接入变更记录](docs/DIGITAL_HUMAN_INTEGRATION_20260803.md)。

这是一个自包含的剪映草稿采集、素材管理、批量生成和处理机服务项目。源码、前端、母版、素材库以及 `jy-draftc` 解密程序都已经放进本项目目录；构建缓存放在项目外，因此整个 `jyd_plain_json_probe` 文件夹可以直接压缩并迁移。

> 当前渲染链路依赖 Windows 剪映客户端和 Windows UI 自动化。中央网站可以独立部署，但实际导出的 Agent 必须运行在安装了剪映且桌面会话保持可用的 Windows 电脑上。

运行日志按组件持久化并自动轮转：Processor 使用 `data/logs/workbench.log`，本地渲染使用
`data/logs/render.log`，内嵌 Collector 使用 `data/logs/collector.log`；独立 Agent 使用
`%LOCALAPPDATA%/JianyingRenderAgent/logs/agent.log`。默认单文件 10 MB、保留 14 天，凭据在
写入前脱敏。

新版工作台顶部“运行记录”只展示当前项目的重要步骤和状态；需要协助排查时，可从同一窗口
下载仅限当前项目的脱敏诊断包。诊断包不会包含完整脚本、素材文件或路径、操作负载和登录凭据。

## 最常用的四个入口

```powershell
# 启动处理机网站（新版工作台默认 http://127.0.0.1:8010/app/new）
.\start_processor.ps1 -ProcessingMode standalone

# 启动本机草稿读取/上传工具（后台运行，不需要打开独立页面）
.\start_collector.ps1

# 启动隔离的测试网站与测试采集器（分别在两个 PowerShell 窗口运行）
.\start_test_processor.ps1
.\start_test_collector.ps1
# 测试页面：http://127.0.0.1:8001/app

# 多处理机模式：中央服务与独立处理机 Agent
.\start_processor.ps1 -ExecutionMode agent
# 不带参数会打开图形启动器
.\start_agent.ps1

# 重新生成采集器、中央服务和处理机 Agent 三个 Windows 发布包
.\build_release.ps1

# 当前单处理电脑部署：快速生成服务器和采集器两个包
.\build_deployment.ps1

# 生成包含最新三个发布包、源码、素材库、母版和解密工具的完整项目 ZIP
.\build_portable_project.ps1 -BuildReleases
```

## 本机与公用机切换

- 员工自己的处理端使用默认 `standalone`，启动器访问 `http://127.0.0.1:8010/app/new`，视频直读本机路径；旧工作台仍保留在 `/app`。
- 普通用户账号和数字人任务统一来自数字人网站；本地默认连接 `http://127.0.0.1:8000`。
- 公用机使用独立发布包 `release/JianyingRenderServer-shared-windows-x64.zip`。它默认监听 `0.0.0.0`、继续用公用机自身的一套剪映顺序处理，不启用多 Agent 调度。
- 公用机页面继续显示同一组“本机处理 / 公用处理机”卡片；点击“本机处理”会返回员工电脑的 `http://127.0.0.1:8010/app`。

只生成公用机包：

```powershell
.\build_shared_processor.ps1
```

### 数字人账号与任务收件箱

工作台不再单独维护普通用户账号。本地测试使用本机数字人网站账号：

```text
http://127.0.0.1:8000/admin
```

工作台登录时由数字人网站验证账号并签发短期令牌，不保存用户密码。进入“数字人任务”后，每 15 秒自动拉取当前账号自己的任务：单条文本语音视频可一键导入视频和精确字幕；上传音频或多片段任务提供原始片段下载，人工粗剪后再选择成片。正式部署时在 `data/processor_config.json` 设置 `digital_human_server_url` 为正式数字人网站 HTTPS 地址，服务器现有账号无需迁移。

### 新版工作台与统一项目骨架

新版页面由工作台托管在 `/app/new`，成果库和声音中心分别使用
`/app/new/gallery`、`/app/new/voices`。新版登录页复用数字人网站账号，浏览器只持有
工作台设置的 HTTP-only 会话 Cookie；未登录访问会返回 `/app/new/login`，不会在
前端保存数字人访问令牌。

工作台已提供 `/api/new/projects` 统一项目接口作为后续业务模块的数据基础。一个项目
包含多条脚本行，每行分别保存当前音频、当前画面合成视频、原始视频片段、变体、字幕
绑定和历史素材版本。项目、素材、异步操作和外部批次关联全部绑定数字人账号；普通用户
只能访问自己的项目。

新版输入模块已经接通真实接口：用户可下载固定两列的 Excel 模板，上传 `.xlsx`/`.csv`
脚本，批量上传 JPG/PNG/WEBP，并选择“每图连续复用 N 行”或“逐行循环”策略。任务 ID、
脚本、图片池、逐行当前图片和图片历史版本均由工作台保存，刷新页面可恢复。

声音模块也已经接通真实接口：声音中心读取当前数字人账号的三个 MiniMax 官方音色及
已保存的克隆/融合音色，可先生成制作结果、试听后再保存到音色库；核心工作台的项目
默认音色会一次应用到全部脚本行，各行仍可单独覆盖。显式确认费用后可生成音频、轮询
状态、试听、下载和失败重试。生成结果及 MiniMax
原始时间戳会保存为项目素材版本，流程停在声音审核边界，不会自动创建 RunningHub
画面任务。声音请求只提交脚本、音色和语音参数，不上传项目图片。

画面模块 4A 已接通真实接口：用户再次确认 RunningHub 费用后，工作台后端调用数字人
后端原有任务链；此时才上传各行当前图片并与已审核音频绑定。随后轮询单/多片段状态，
下载并保留所有成功的 RunningHub 原始分段，再
保存按音频时长标准化的 `base_video`；多片段接缝使用 0.25 秒保时长叠化。页面显示真实
状态并支持预览、下载与失败阶段重试。音频完成后、4A 启动前仍可替换图片，4A 会使用
最后一次选择的当前图片。

模块 4B 使用 `base_video`、MiniMax 原始字幕时间戳、用户选择的真实字体和可选 BGM
生成浏览器完整预览配方，普通预览不启动剪映，也不提前导出中间 MP4。字幕固定居中
单行、最大宽度为画面 80%、距底部约 20%；长句按真实字体字宽在原 cue 时间内拆成
连续字幕，无法安全排版时标记 `REVIEW_REQUIRED`。BGM 在浏览器中按 0.3 音量与视频同步。
用户明确下载普通成片时才按需调用现有剪映队列导出一次；后续变体直接把基础视频和同一
字幕/BGM 配方放入变体任务，不能要求先导出普通成片。4B 不重新调用 RunningHub，也不
自动生成变体。

智能内容分析模块 5 已把数字人后端的单脚本分析接口接入工作台。Excel/CSV 导入和脚本编辑
只保存或失效快照，不自动分析；用户点击“生成声音预览和脚本分析”后，工作台才对本批声音目标中首次
导入或文本变化的 `ProjectItem` 发起分析，一行一次请求，单批最多并发 10 行。仅重新生成
声音而文本未变时不会重做分析；显式内容分析重试仍可强制刷新。每行独立保存音乐与字幕
分支状态、合法结果、稳定错误摘要和服务端版本信息。分析失败不会清空 MiniMax `raw_cues`、音频、基础视频
或成片，也不会触发 MiniMax、RunningHub 或剪映。单行分析点击后立即显示“AI 分析中”；
音乐分支成功时会同时保存并在下拉框显示具体 Top1 曲目。

智能内容分析模块 6 已把合法 `subtitle_units` 映射到当前 MiniMax `raw_cues`：只有脚本、
分析快照、当前音频脚本摘要和 raw cues 音频绑定一致时才使用语义断点，再按抖音美好体
11 号真实字宽、13em 单行上限生成 `render_cues`。连接词、数字、专有词和禁止断开的关联
单元不会在语义路径内部拆开；单个模型语义组意外超宽时只局部补切并保留其他 AI 断点，
不再整篇回退。句号、问号、感叹号、分号和换行是不可跨越的硬边界，逗号、顿号和冒号是
可按宽度调整的优先边界；排版器会把“表现/储存/世界冠军”等完整词及孤立助词作本地兜底。
模型断点和本地超宽补切共用同一套安全词边界：模型若返回“核心｜逻辑”等错误边界会先合并，
超宽组也只能在“新中年女性｜健康体重管理”等安全位置切分，不再按字符数均分完整词。
空格和换行允许不出现在 MiniMax cue 文本中，`~` 必须精确匹配；版本或原文映射失败仍会
保留 `raw_cues` 并回退旧排版。

智能内容分析模块 7 已把合法 `music_intent` 接入 46 首本地标签库并只选择唯一 Top1。
音乐分析或匹配失败时按项目默认音乐、无 BGM 降级，不阻止字幕或 4B 预览；手动曲目和
手动无 BGM 都不会被 AI 静默覆盖。当前音频变化而文本不变时复用内容分析并保留界面当前
推荐；同一脚本显式重试字幕分析时也保留已经成功选择的自动音乐，不重新抽取 Top1。4B 前
再按新音频真实时长复核选择；变体冻结继承 4B 最终配方，不把 BGM 作为变体维度。

智能内容分析模块 8 已完成跨项目 mock 验收。数字人服务端实际响应可直接通过工作台校验、
语义时间映射和 Top1 匹配；完整成功、两种部分成功、索引安全修复、空格/换行/`~` 精确
处理均已覆盖。最终完整回归为数字人 `216 passed`、工作台 `260 passed`，未调用真实付费
服务或部署生产。

模块 5 已完成 9:16 视频预览和当前视频版本替换。播放开始后中央播放按钮自动隐藏，点击
画面可暂停；“下载原始素材”在单片段时直接返回 RunningHub MP4，多片段时返回包含全部
片段和顺序清单的 ZIP。上传本地 MP4/MOV/AVI/MKV/WebM 后创建新的
`composition_video` 版本并切换当前指针，自动视频和全部原始片段继续保留；原字幕时间轴
标记为 `INVALIDATED`，不会错误叠加到用户已经处理好的视频上。

模块 6 已完成真实剪映变体批次。默认同时使用视频特效、全屏贴纸和画面变化套装，并以
加权最大最小距离挑选组合，使 30 个版本优先覆盖明显不同的裁剪、颜色、特效及贴纸；补充
生成会避开已经成功的签名。字幕字体与 BGM 冻结继承模块 4B，不参与轮换。封面保持逐行
手动设置，使用第一帧并固定作为主视频轨道最前 3 帧；原主视频、原声、BGM、字幕、特效和
贴纸统一后移，封面不会作为额外视频轨道覆盖正文。支持真实进度、部分成功、只重试失败项、
补充生成、预览下载及单个删除。

模块 7 已把成果库接入真实变体数据，并把模块 6 的预览统一修正为 `9:16`。每次生成、补充
或重试都会分配一个当日批次目录，默认根目录为 `D:\auto`，结构为
`D:\auto\月.日\批次号`；原始 XLSX/CSV 会在剪映提交前复制到同一目录，MP4 直接导出到
该目录。成果库按账号权限结合数据库索引和实际文件状态，支持项目、日期、批次、状态、

账号归属校验，再在单一数据库事务中删除记录；任一素材不存在或无权访问时整批不删除。受管
导出文件会随记录一起移除。可用 `JYD_RESULT_LIBRARY_ROOT` 覆盖根目录。

2026-08-05 的交互修正中，成果库首页改为批次级缩略卡，点击后才展开该批次的 9:16
变体；同时提供“全选全部成果”和“全选本批次”。配置表脚本文案列使用固定宽度、自动
断词和列内纵向滚动，长文案不会再把表格持续向右撑开。4B 默认字幕字体固定初始化为
素材库中的 `DouyinSansBold`（抖音美好体），已保存的历史字体设置仍保留。

核心工作台左侧脚本、声音和图片输入区支持收起/展开并记忆本机选择；收起后右侧配置表
占满工作区。表头以低饱和靛蓝标线和圆点标记需要导入、选择或操作的列，以青绿色标线
和圆点标记声音、视频和变体预览结果；标题栏同时显示图例，表格正文配色不变。

新版配置表在任务完成后仍允许修改脚本、音色、图片、BGM 和字幕样式。修改不会覆盖或
删除旧素材：脚本/音色变化会创建新的声音及后续任务链，图片变化只重新开始画面及成片，
BGM/字幕变化只重新生成浏览器预览配方。全部声音已生成后，“重新生成声音预览和脚本分析”仍可点击，
并在费用确认后创建新的音频版本。只有对应行正在异步生成时才暂时禁止修改。
字幕样式卡固定使用“这是字幕预览”展示字体和颜色，不再截取脚本文案。BGM 下拉框不展示
内部“AI 智能匹配”模式：匹配成功后直接选中实际曲目，尚未得到匹配结果时显示“无音乐”。
配置表每条任务在任务 ID 下提供删除入口，与“添加分段”对称。草稿、失败和已完成任务可在
二次确认后删除；正在生成或分析的任务禁止删除。任务可以删到 0 行，再通过“添加分段”重新
创建；删除单行不会影响项目公共图片池或其他任务。
底部“一键下载未变体视频”会把所有脚本行当前的普通成片打成一个 ZIP，不包含变体视频；
若某行只有浏览器动态预览，点击后会在用户确认下逐条启动剪映导出，全部完成后统一下载。

自定义音色保存后先以“未激活”状态显示在声音中心，用户明确确认后点击“激活”，由
数字人后端执行第一次正式语音合成并记录为 `ACTIVE`；只有官方音色和已激活自定义音色
能进入核心工作台。自定义音色卡可二次确认后删除；仍被项目选中的音色必须先更换。

向日葵更新已有公用机时，使用 `JianyingRenderServer-update-windows-x64.zip` 覆盖程序文件并保留原 `data` 目录，避免丢失账号、素材和任务数据。

工作台素材和机器设置仍保留独立技术管理员，入口为 `/local-admin/login`；普通员工账号只在数字人网站管理。采集器内部接入密码仍可通过 `JYD_SITE_PASSWORD` 修改，处理机令牌首次启动生成在 `data/web_storage/agent_token.txt`。多处理机部署见 [docs/MULTI_PROCESSOR.md](docs/MULTI_PROCESSOR.md)。

日常操作统一在中央网站 `/app` 完成：上传 MP4、扫描并导入本机剪映草稿、选择素材、提交批量任务以及下载结果都不需要切换页面。本地采集器和剪映 Agent 仍是两个后台进程，分别负责读取本机文件和控制剪映。

本机独立模式下，采集器还负责选择本机视频和导出目录。视频只登记本机路径，不经过网页上传；结果页改为“打开视频 / 打开所在文件夹”。公共素材继续位于 `data/libraries`，个人素材库首次为空，用户可从自己的剪映草稿一键采集到 `data/personal_libraries`。公用处理机模式仍保留原有上传、网页预览和下载流程。

## 正式环境和测试环境

- 正式网站固定使用 `http://127.0.0.1:8010/app`，数据保存在 `data`。
- 测试网站默认使用 `http://127.0.0.1:8001/app`，测试采集器默认使用 `http://127.0.0.1:8766`。
- 测试数据库、母版、素材库副本、上传文件和任务输出都保存在 `runtime/test_environment`，不会修改正式数据。
- 第一次启动测试环境时会从正式 `data/libraries` 和 `data/template_library` 复制初始数据；之后两边独立变化。
- 需要重新用正式数据初始化测试环境时，先停止测试进程，再运行一次 `.\start_test_processor.ps1 -ResetData`，随后正常启动测试采集器。不要同时在正式环境和测试环境提交剪映导出任务，两边仍会控制同一个本机剪映。

处理机启动器第一次使用时填写中央服务地址和令牌、确认剪映草稿目录并选择“一号处理机/二号处理机”；设置会保存在当前 Windows 用户目录，之后启动时不需要重复填写。发布包用户直接双击 `JianyingRenderAgent.exe` 即可打开同一界面。

## 目录用途

```text
apps/                 可运行和可打包的三个应用
  collector/          本机草稿读取/上传服务和 PyInstaller 配置
  processor/          中央网站/API、统一前端和 PyInstaller 配置
  agent/              剪映处理机 Agent 和 PyInstaller 配置
data/                 需要随项目迁移的业务数据
  libraries/          音乐、字体、贴纸、花字、特效、文字模板等素材库
  template_library/   已导入的剪辑母版
  web_storage/        账号、任务、上传记录和生成结果
docs/                 各功能说明和历史开发文档
examples/             渲染任务 JSON 示例
release/              最终交付用 ZIP
runtime/              解密副本、隔离测试环境、测试临时文件和本机运行状态（不进入正式项目 ZIP）
scripts/              环境安装和打包脚本
src/jyd_probe/         核心 Python 源码
tests/                 自动测试
tools/                 素材提取、草稿诊断和旧任务工具
```

## 换电脑继续开发

1. 直接压缩整个项目目录，或者运行 `.\build_portable_project.ps1`。
2. 在另一台 Windows 电脑解压。
3. 安装 Python 3.11，然后运行：

```powershell
python -m pip install -r .\requirements.txt
```

4. 使用 `.\start_processor.ps1 -Python "C:\你的Python路径\python.exe"` 启动。
5. 如果要重新生成免 Python 的发布包，先运行：

```powershell
.\scripts\setup_build_environment.ps1 -Python "C:\你的Python路径\python.exe"
.\build_release.ps1
```

构建环境和 PyInstaller 临时产物会放在项目同级的 `.jyd-build-cache`，不会污染项目目录。

## 素材提取示例

所有提取工具都在 `tools\library`。例如按剪映草稿名提取并分类音乐：

```powershell
D:\Myanaconda\python.exe .\tools\library\export_audio_library.py `
  --draft-dir "D:\剪映草稿\JianyingPro Drafts\音乐采集_鸡汤人设" `
  --category-from-draft-name
```

默认输出会进入 `data\libraries` 下对应的素材库。

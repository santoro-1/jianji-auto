# 剪映批量剪辑工作台更新说明

这个压缩包只用于更新已经安装好的工作台，包含重新构建的 Processor 程序、完整 `_internal` 依赖、内嵌网页前端、
解密工具和本说明。包内不会出现 `data` 目录，因此不会携带或覆盖语义素材、音乐、字体、
模板、用户任务、密码、配置、数据库、个人素材库或其他历史数据。

公共素材首次交付使用完整 Processor 包；以后需要单独更新素材时，应制作和审核独立素材包，
不能借用 `-UpdateOnly` 程序更新包。

本包也不包含本地 ASR。H3 片头声音清理和精确字幕需要可用的 ASR；新电脑首次安装应使用
包含 ASR、FFmpeg 和公共素材的完整包，不能只把代码更新包解压到空目录。
详细打包和首次安装命令见 [2026-08-31 发布指令](https://github.com/santoro-1/jianji-auto/blob/main/jyd_plain_json_probe/docs/RELEASE_20260831.md)。

## 更新步骤

1. 等待正在导出的任务结束。
2. 关闭全部工作台网页，并退出“公域闪剪工作台”统一启动器。
3. 建议照常备份原工作台目录中的 `data` 文件夹；更新包不会修改它。
4. 解压本更新包，把全部文件复制到**直接包含 `JianyingRenderServer.exe` 的原目录**并选择覆盖。统一安装对应外层目录下的 `digital-human`，不要覆盖到启动器所在外层目录；独立安装对应 EXE 所在目录。
5. 不要删除原来的 `data` 文件夹；程序继续读取其中已有的任务、配置和素材。
6. 原来使用统一安装的，回到完整工具根目录，双击 `PublicVideoWorkbenchLauncher.exe`；原来使用独立工作台的，按原入口启动工作台即可，不需要新增 LTX。
7. 浏览器按 `Ctrl+F5`，确认原有素材和最近任务仍然存在。使用 LTX 的统一安装还应确认视频对口型可以上传人物视频。
8. 检查 `http://127.0.0.1:18084/healthz`。健康检查只证明 ASR 进程可用；首次安装还应实际转写一次短音频，确认模型能加载。失败时查看 `data/logs/asr.log`。

新版工作台会在运行期间监督本地 ASR，连续健康失败后最多自动拉起 3 次，并且只对中断的当前
识别重试一次。若启动窗口提示恢复次数耗尽，请同时提供 `data/logs/asr-supervisor.jsonl` 和
`data/logs/asr.log`；前者包含 PID、启动/停止、退出码、工作台主动关闭标记、重启次数和当时
系统资源，能够区分正常退出、异常崩溃和反复启动失败。

启动窗口中的“剪映草稿目录来源”应显示“剪映本机索引”或“手工配置”。程序会读取当前
Windows 用户的剪映 `root_meta_info.json`，不会把制作更新包的电脑路径带到新电脑。若显示
“安装目录临时兜底（未确认）”，先打开剪映并打开任意草稿，然后关闭并重新启动工作台；
仍无法识别时，在原安装目录的 `data\processor_config.json` 中填写该电脑自己的
`draft_root`。不要把另一台电脑的盘符和目录原样复制过来。

项目数据库 v12 起，`project_assets`、`project_input_images` 和
`project_script_sources` 在库内使用 `storage://...` 相对引用，业务接口仍返回基于当前
`data/web_storage` 解析出的绝对路径。首次从旧版本启动时，程序会先生成
`data/web_storage/control.db.pre-project-v12.bak`，再在同一数据库事务中转换可确认的旧路径。
如果整套程序移动了目录，必须连同原 `data/web_storage` 一起复制；云端成功产物可以重新下载，
但只存在于本地的上传图片和参考视频不能凭空恢复。

统一安装需要同时使用视频对口型时，不要单独双击 `digital-human` 目录中的 `JianyingRenderServer.exe`；这种启动方式不会启动 LTX 服务。
如果不确定原工作台目录，请不要更新，先联系维护人员。把更新包解压到新文件夹单独运行，会得到一个没有原素材和任务记录的新工作台。

# AI 标题与固定封面开发文档

日期：2026-08-10

## 1. 目标与职责边界

每条项目任务只保存一份标题结果，由项目后处理、普通成片和后续全部变体共同继承。封面不再属于
模块 6 的人工变体参数，也不允许每个变体单独填写。

- 大模型只负责根据原脚本生成标题文字。
- 本地工作台负责校验、持久化、固定视觉参数和剪映渲染。
- 封面底图固定使用该任务当前上传的原始人物图片 `item.inputs.image.managed_path`，不从数字人视频截图。
- 没有合法标题时不生成占位封面，前端显示“等待 AI 标题”。
- 本阶段不调用真实付费大模型；先完成标题契约和渲染链。

## 2. 数据归属

标题保存在 `item.settings.postprocess`：

```json
{
  "cover_title": {
    "line_1": "健康真相",
    "line_2": "别再踩坑"
  },
  "top_title": {
    "label": "减肥大实话",
    "headline": "只有坚持才能达成目标"
  }
}
```

`cover_title` 必须同时提供两行。每行去除首尾空白后不得含空格或换行，最多 5 个字符；任一行为空
或超长均拒绝保存。`top_title` 沿用现有规则：黄色标签最多 12 字，白色主标题最多 20 字。

标题变化只使后处理成片失效，不重新调用 MiniMax 或 RunningHub。变体请求不再接受或保存独立
`cover`；历史客户端传入的该字段只兼容忽略，不能覆盖项目标题。

## 3. 固定封面参数

基准画布为 1080×1920、9:16，封面持续 3 帧。剪映 UI 的 Y 值按项目既有换算规则写为
`transform_y = UI_Y / 1920`。

| 项目 | 第一行 | 第二行 |
| --- | --- | --- |
| 字体 | 思源粗宋 / `SourceHanSerifCN-Heavy` / `6807742980271641102` | 同左 |
| 字号 | 35 | 27 |
| 颜色 | `#FADF4A` | `#F5F6F0` |
| 位置 | X=0，Y=-160 | X=0，Y=-655 |
| 缩放 | 100% | 100% |
| 字间距 / 行间距 | 0 / 6 | 0 / 6 |
| 对齐 | 水平居中 | 水平居中 |
| 阴影颜色 | `#000000` | `#1F1A05` |
| 阴影 | 90%，模糊 15%，距离 5，角度 -45° | 50%，模糊 15%，距离 5，角度 -45° |

底部黑框使用普通混合、50% 不透明度、100% 缩放、X=0、剪映 UI Y=-420。当前图片层实现把黑框
直接合成进封面 JPEG：中心比率 `0.609375`，宽度比率 `1.0`，高度比率 `0.36`。上传图片先用
居中 cover 裁切适配实际草稿画布，再合成黑框；文字仍保留为可编辑剪映文本轨道。

封面插入时间线最前 3 帧，正文视频、语音、字幕、BGM、顶部标题、人名板和语义素材整体后移，
因此正文元素不会出现在封面上。

## 4. 大模型返回规划

后续扩展现有“统一内容分析”请求，在同一次模型调用中增加 `titles` 分支，禁止为了封面再发起
第二次付费调用。建议响应结构：

```json
{
  "schema": "jyd.unified-content-analysis.v3",
  "titles": {
    "cover": {
      "line_1": "健康真相",
      "line_2": "别再踩坑"
    },
    "video": {
      "label": "减肥大实话",
      "headline": "只有坚持才能达成目标"
    }
  }
}
```

提示词要求：

1. 只依据当前脚本，不补造疗效、数字、身份或结论。
2. 封面第一行表达主题，第二行表达具体冲突、结果或行动钩子；每行 2～5 字，硬上限 5 字。
3. 一眼能理解重点，避免“震惊”“一定要看”等空话、废话和无信息口号。
4. 顶部标签用于稳定栏目归类，主标题用于完整概括本条核心观点。
5. 只输出结构化 JSON；不得返回字体、颜色、坐标、图片路径、素材 ID 或时间参数。

本地接收层必须把 `titles` 当作独立分支校验：标题失败不能覆盖已成功的音乐、字幕或视觉分析；
模型输出经长度、空白、成对字段和脚本依据校验后，才分别写入 `postprocess.cover_title` 与
`postprocess.top_title`。缓存键应包含脚本 SHA-256、分析 schema 版本和提示词版本，脚本不变时复用，
脚本变化时仅使当前行标题失效。

## 5. 渲染流程

```text
统一内容分析 -> 保存 cover_title/top_title -> 4B 浏览器预览配方
                                      -> 普通成片导出：同一封面
                                      -> 模块 6 变体：继承同一封面
```

普通导出和变体都调用 `build_project_cover()` 构建同一固定配方。变体数量、背景色、贴纸和特效可以
变化，封面文字、底图和固定样式不参与差异组合。

## 6. 验收标准

1. 封面底图等于任务当前输入图片，不等于数字人或 SeedVR2 视频帧。
2. 两行标题、字体、字号、颜色、位置、阴影和黑框参数与本文件一致。
3. 封面严格占 3 帧；正文所有轨道从第 4 帧开始。
4. 普通导出和所有变体冻结同一 `postprocess.cover_title`，变体接口没有手工封面要求。
5. 标题缺失时无占位封面；非法标题在进入渲染队列前失败。
6. 标题设置变化不调用 MiniMax、RunningHub 或 SeedVR2。

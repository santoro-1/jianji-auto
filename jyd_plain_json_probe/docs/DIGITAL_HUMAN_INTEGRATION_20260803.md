# 数字人任务接入剪映工作台变更记录（2026-08-03）

## 状态

本轮工作台改造已在本地代码完成并通过测试，尚未部署。普通用户账号改为复用数字人网站账号；工作台本身只保留素材、机器和运行设置所需的技术管理员。

## 连接方式

- 工作台服务端口改为 `8010`，避免与数字人网站的 `8000` 冲突。
- 本地默认数字人地址为 `http://127.0.0.1:8000`。
- 配置字段统一为 `data/processor_config.json` 中的 `digital_human_server_url`。
- 旧配置中的 `http://192.168.11.28:8000` 或旧云端认证地址会迁移到本地默认地址；用户明确填写的正式数字人地址不会被覆盖。
- 正式上线时只需把 `digital_human_server_url` 改为云端数字人网站 HTTPS 地址，无需迁移云端现有账号。

## 登录与管理员边界

- 普通用户在工作台输入账号密码后，由数字人网站完成验证；工作台不保存密码，只保存短期会话令牌。
- 工作台 `/admin` 不再作为普通账号管理入口，而是跳转数字人网站 `/admin`。
- 工作台独立技术管理入口保留为 `/local-admin/login`，用于素材、机器和本地运行设置。
- 数字人账号被停用、删除或修改密码后，现有工作台会话失效。

## 数字人任务收件箱

工作台新增“数字人任务”区域，每 15 秒刷新当前登录账号自己的任务。刷新只更新列表，不会自动下载、自动导入、自动渲染或自动发布。

| 数字人任务 | 工作台动作 |
| --- | --- |
| `AUTO_READY` 且 `AUTO_POSTPROCESS` | 显示“一键导入工作台”，下载唯一完整视频并载入精确字幕时间戳 |
| 上传音频任务 | 显示需要人工处理，并提供原始片段下载 |
| 文本语音被切成多个片段 | 显示需要人工处理，并提供每个原始片段下载 |

自动导入成功后会切换到视频生成页面、选中本地视频源并填入字幕。操作人仍需选择 BGM、字幕字体/样式、保存目录并确认渲染。

## 工作台新增接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/digital-human/tasks` | 拉取当前登录账号的数字人任务 |
| `POST` | `/api/digital-human/tasks/{item_id}/import` | 导入唯一的自动后期视频及精确字幕 |
| `GET` | `/api/digital-human/tasks/{item_id}/videos/{video_index}` | 下载人工处理任务的指定原始片段 |

上述接口使用工作台当前会话，并由服务端携带短期令牌访问数字人网站，不把令牌暴露给前端下载地址。

## 字幕规则

- 渲染接口支持精确字幕 cue JSON 和 SRT，能够保留数字人网站返回的开始、结束时间。
- 字幕预览使用同一套校验逻辑；重叠、逆序或无效时间段会拒绝。
- 视频尾部与最后一句字幕只存在不超过 1 秒的小误差时，会裁到视频结尾；更大的不一致会报错，避免静默错位。
- 用户编辑字幕文字或更换视频源后，已导入的精确 cue 会失效，工作台按新内容重新处理。
- 上传音频或多片段任务建议先人工粗剪，再使用剪映字幕识别和人工校对。

## 本地文件与保存目录

- 从数字人网站导入的视频作为本地媒体引用保存，不上传阿里云。
- 输出目录继续由操作人在本机选择，并使用浏览器本地存储记住上一次选择。
- 本轮未增加自动发布；完成的本地视频仍按原工作台流程交给后续服务。

## 本地联调步骤

1. 先启动数字人网站，确认监听 `http://127.0.0.1:8000`。
2. 再运行 `start_processor.ps1`，打开 `http://127.0.0.1:8010/app`。
3. 使用同一套本地数字人测试账号登录工作台。
4. 打开“数字人任务”，确认任务列表在 15 秒内出现。
5. 用单片段文本任务测试一键导入和字幕预览。
6. 用多片段文本任务、上传音频任务测试逐段下载。
7. 选择本地输出目录完成一次渲染，确认目录选择被记住。

## 2026-08-04 新版模块 3 补充

- `/app/new/voices` 已复用数字人网站原有声音克隆、融合、试听和保存能力，不建立第二套
  声音资产或 MiniMax 配置。
- 核心工作台已通过 `/api/new/voices*` 和 `/api/new/projects/*/audio*` 接入官方音色、
  逐行音色、批量声音生成、状态同步、试听、下载和单行重试。
- 项目默认音色由工作台后端原子地应用到全部脚本行，单行接口仍可覆盖；声音中心明确为
  “生成试听、试听确认、保存到音色库”三步，未保存的制作结果不会进入工作台选择列表。
- 保存后的自定义音色需要用户显式点击“激活”，由数字人后端完成第一次正式 TTS 并切换
  `ACTIVE` 后才能供核心工作台选择；自定义音色卡支持二次确认删除，项目仍引用时拒绝。
- 工作台保存 `digital_human_audio_batch`、`digital_human_audio_item` 关联、音频素材历史
  版本和 MiniMax 原始字幕时间戳；项目状态和按钮权限由后端返回。
- 音频批次固定停在数字人后端 `AWAITING_REVIEW`，本模块不会自动进入 RunningHub。
- 声音生成只提交脚本、音色和语音参数，不上传图片；用于远程批次的内部幂等键采用固定
  长度哈希，避免项目编号和音色编号拼接后超过数字人数据库字段长度。
- 自动化测试全部 mock MiniMax，没有产生真实费用；没有部署服务器或修改云端账号数据库。

## 2026-08-04 新版模块 4A 补充

- 工作台新增项目画面启动、真实状态轮询、单行失败阶段重试和基础视频下载接口；浏览器
  仍只访问工作台后端，账号令牌只由工作台服务端代理。
- 用户明确确认费用后，工作台才让数字人后端现有音频审核任务进入 RunningHub；没有
  建立第三套后端、账号、任务队列或 RunningHub 调用实现。
- 工作台在这个 4A 动作中才上传脚本行的当前图片，并由数字人后端绑定到已审核音频；
  图片不会提前参与模块 3 的声音任务。
- 每个 RunningHub 成功分段都下载为不可覆盖的 `original_video_segment`；单/多片段均
  生成按已确认音频时长标准化的 `base_video`，多片段按顺序自动拼接。
- `base_video` 不等于最终 `composition_video`。4A 页面禁用字幕、BGM 和变体操作，基础
  视频完成后不会自动创建变体。
- 音频完成后、4A 启动前仍允许替换当前图片；4A 上传并绑定最后一次选择的图片。

## 2026-08-04 新版模块 4B 补充

- 4B 完全位于工作台后端；没有增加数字人接口、第三套后端、账号或渲染队列，浏览器仍
  只调用工作台 `/api/new/*`。普通预览不启动剪映，明确下载时才复用现有
  `RenderJobQueue` 和剪映处理机按需导出一次。
- MiniMax 原始 cues 永久保留；派生 render cues 固定居中单行、最大宽度 80%、中心距底部
  约 20%，并按用户选择的真实字体文件测量字宽，禁止自动换行。无法安全排版时进入
  `REVIEW_REQUIRED`，不创建预览或剪映任务。
- 可选 BGM 来自工作台现有音乐库，浏览器完整预览按 0.3 音量与 `base_video` 同步；字幕
  按 render cues 随音频内容动态变化。只有明确下载才登记新的 `composition_video`。
- 后续变体直接使用基础/上传视频和同一字幕/BGM 配方，在变体任务中一次剪映导出；不先
  导出普通成片，因此不会重复控制剪映。4B 不重新触发 RunningHub，完成后不自动生成变体。

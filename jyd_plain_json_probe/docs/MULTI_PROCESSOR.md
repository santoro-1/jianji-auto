# 剪映处理电脑接入说明

> 设备授权开发分支注意（2026-09-01）：独立 Agent 已接入实际中央接口、执行机账号/原设备密钥和持久执行回执，但人工核实恢复、真实设备/GUI、发布公钥与完整包验收仍未完成，暂不打包分发。普通“每台电脑部署一份公用工作台”的内置处理方式不是此 Agent 协议。当前开发接入规则见下节；后面的旧版使用说明仅作历史参考，不能只填旧接入密码就作为防复制版本交付。

## 受保护 Agent 的开发接入规则

1. 明确两个地址：中央工作台地址用于领任务，数字人授权网站用于登录和校验设备，不能互相替代。授权网站必须匹配程序内的可信公钥配置；当前仓库配置为空，不能直接打包使用。
2. 首次设备申请/批准应在实际执行剪映的电脑上完成。Agent 本身只读取原设备密钥，不自动初始化、申请或更换身份；不要在操作人员的浏览器电脑上申请后以为远程处理机已激活。
3. GUI 填中央地址/接入密码，以及网站授权地址、网站用户名和本次密码；网站密码/登录令牌不会保存。每次启动可能需要重新登录，这是账号登录，不是设备重新激活。
4. Agent 只能领取属于登录账号、具备实际草稿/导出权限的任务；一把已验证设备密钥在同一中央队列最多一个运行任务，改电脑备注或账号不能增加槽位。多个 Windows 用户的实际行为还需验收。
5. 正常更新复用机器原密钥及原批准关系，并保留 `%LOCALAPPDATA%\JianyingRenderAgent`。此目录包含配置、日志及 `execution-receipts.sqlite3`，不应混入分发包，也不能为了“重试”而删除。

断线后的处理：领取/启动确认丢失时续接原编号；结果已保存时只补报，不重新渲染。设备停用后仍可在原网站账号有效、原密钥可用时补报原任务结果，但不能领新任务。若提示执行结果不明，先保留回执、草稿、输出和日志等待核实；受控人工恢复工具尚待开发，不通过删文件、改 SQL 或重新提交解除暂停。退出程序会等待当前单元安全收尾。

CLI 的 `--device-user` / `--device-token-stdin` 与 `--device-auth-server-url` 用于同一账号/设备会话；不要在命令参数中传网站密码。协议、模块和模拟回归范围见 [设备授权主文档第 23 节](../../../数字人/runninghub_mvp/工作台设备授权与免重复激活开发文档.md#23-独立-agent-接入与持久执行回执2026-09-01)。

## 旧版使用说明（历史参考）

这个压缩包只用于增加执行剪映导出的电脑。普通使用者不需要安装它。

## 使用前准备

1. 先由负责人启动“公用剪映工作台”。
2. 当前电脑安装了可正常导出的剪映专业版。
3. 关闭自动休眠，运行期间不要锁屏。
4. 向负责人索取两项内容：`工作台地址`和`接入密码`。

程序已经包含运行环境，不需要安装 Python、Anaconda，也不需要输入命令。

## 第一次接入

1. 完整解压 ZIP。
2. 双击 `JianyingRenderAgent.exe`。
3. 给这台电脑选择一个名称，例如“一号处理电脑”。
4. 在“工作台地址”中粘贴负责人提供的地址。
5. 在“接入密码”中粘贴负责人提供的密码。
6. 确认剪映草稿目录；自动识别正确时不需要修改。
7. 点击“保存并启动”。

设置会自动保存。以后只需双击程序并点击启动。

## 怎么判断连接成功

启动窗口会显示已经连接，公用工作台顶部也会显示在线处理电脑数量。每台电脑同一时间执行一个任务，多台电脑会自动分担队列，不需要手动指定任务。

## 使用期间注意

- 保持剪映登录和桌面解锁。
- 不要同时人工操作剪映。
- 不要退出启动器。
- 电脑可以处理其他后台工作，但不建议进行会抢占鼠标、键盘或剪映窗口的操作。

## 连接失败

1. 确认这台电脑与公用工作台电脑连接的是同一个可互相访问的网络。
2. 重新向负责人复制工作台地址和接入密码，避免多出空格。
3. 确认公用工作台仍在运行。
4. 如果更换了公用工作台电脑，使用负责人最新发来的连接信息。

## 重新设置

重新打开程序，修改工作台地址、接入密码或草稿目录，再点击“保存并启动”即可。配置保存在：

`%LOCALAPPDATA%\JianyingRenderAgent\config.json`
